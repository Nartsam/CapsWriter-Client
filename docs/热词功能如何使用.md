# 热词功能如何使用

## 什么是热词

热词功能用于修正语音识别结果中的特定词汇。比如你 "CapsWriter" 是一个非常见词，可能被识别成 "Caps rider"，就可以通过热词进行修正。

客户端提供**两种热词机制**，分别用于不同场景。

---

## 一、客户端强制热词（hot.txt）

### 作用

基于**音素匹配**的强制替换。只要识别文本的音素与热词足够相似（超过阈值），**一定会被替换**。适用于人名、专业术语、英文品牌等识别不准的词。

### 文件位置

项目根目录的 `hot.txt`，修改后**自动热重载**，无需重启。

### 格式

- 每行一个热词
- `#` 开头的行为注释
- 用 `|` 分隔多个别名（写法不同，音素相似，都替换为第一个词）

```text
# 这是注释
Claude | Cloud | 克劳德 | 克劳得
CapsWriter | Caps Rider
我家鸽鸽
```

上例中，如果说 "cloud" 或 "克劳德"，都会被替换为 "Claude"。

### 自定义短语

热词的第一个词不一定是"纠正目标"，也可以是**你希望输入的内容**，后面跟触发别名。这样就可以用作"自定义短语"，用语音快速输入长文本，而不必逐字念：

```text
18200006666 | 我的手机号 | input my phone
上海市浦东新区张江高科技园区 | input my address
hello@example.com | 我的邮箱 | input my email
```

上例中，说"我的手机号"或"input my phone"，都会自动上屏 "18200006666"，不需要一个个数字念。

### 如何添加热词

**方法一**：直接编辑 `hot.txt`，保存后自动生效。

**方法二**：右键系统托盘图标 → **热词**，会用系统默认程序打开 `hot.txt`，编辑后保存。

### 配置项

在 [`config_client.py`](../config_client.py) 中：

```python
hot = True          # 总开关，是否启用音素热词替换
hot_thresh = 0.85   # 替换阈值（越高越精准，越低越容易触发）
hot_similar = 0.6   # 相似阈值（低于 hot_thresh 但高于此值的，只作为 LLM 参考）
```

---

## 二、规则替换（hot-rule.txt）

### 作用

基于**正则表达式**的精确替换。适用于单位转换、符号修正等固定模式替换。（正则语法可参考 [Python 正则表达式](Python%20正则表达式.md)）

### 文件位置

项目根目录的 `hot-rule.txt`，修改后**自动热重载**。

### 格式

```
查找模式 = 替换文本
```

- `=` 两边必须有空格
- 查找模式是正则表达式，支持捕获组
- `#` 开头的行为注释
- 替换侧可用 `\s` 表示空格

### 示例

```text
毫安时     =      mAh
赫兹      =      Hz
(艾特)\s*(QQ)\s*点\s*            =     @qq.
(艾特)\s*(\w+)\s*(点)\s*(\w+)    =     @\2.\4
欧拉玛   =  Ollama
\/sil   =   
\[breath\]  =    
(^逗号[，。]?)|([，。]?逗号$)       =    ，
(^句号[，。]?)|([，。]?句号$)       =    。
(^问号[，。]?)|([，。]?问号$)       =    ？
```

### 配置项

```python
hot_rule = True    # 是否启用规则替换
```

## 三、客户端热词工作流程

```
语音识别结果
    ↓
音素 RAG 匹配（hot.txt）
    ├─ 相似度 ≥ hot_thresh → 强制替换
    └─ hot_similar ≤ 相似度 < hot_thresh → 记作"潜在热词"，可传入角色上下文，用于润色
    ↓
正则规则替换（hot-rule.txt）
    ↓
（可选）角色功能润色
    ↓
输出
```

其实，Qwen3-ASR 已经非常强大，加上热词功能，已经完全不需要 LLM 润色功能。只是 Typeless 有润色，LLM 又这么火，总会有朋友想试试。

## 五、常见问题

**Q: 修改热词文件后需要重启吗？**

客户端监听保存或替换事件，最后一次事件约 0.4 秒后重载；多个文件分别处理。格式错误时保留上次可用内容，并在日志中提示。

**Q: 热词为什么没生效？**

检查以下几点：
- `config_client.py` 中 `hot = True` 是否开启
- `hot_thresh` 是否过高
- 热词是否添加到了 `hot.txt`
- 日志中是否有匹配记录（查看 `logs/client_latest.log`）

**Q: 规则替换的正则语法是什么？**

Python 标准 `re` 模块语法，支持 `\1`、`\2` 等反向引用。

## 六、跨电脑同步与冲突处理

根目录 `hot.txt`、`hot-rule.txt` 不再由程序仓库跟踪。连接服务端后自动合并和同步；首次连接保留双方已有内容，缺失文件会创建。客户端只访问当前识别服务端。服务端在启动和正常退出时同步独立 Git 仓库，配置见服务端的 `docs/热词同步.md`。

保存后会同步到当前服务端及其在线客户端。断网时继续使用本机词库，重连后补传；正常退出时会短暂等待最后一次同步。强制结束进程后，尚未发送的文件修改在下次连接时补传。

同一目标的别名会合并，例如两侧的 `Claude | 克劳德` 和 `Claude | 克劳得` 合并为 `Claude | 克劳德 | 克劳得`。重复项去重，保留注释、空行与已有排版；正常删除依据共同基线传播。规则执行顺序不排序。无法自动合并的规则、删除与修改冲突会生成 `logs/hotword_sync/hot.conflict.txt` 或 `hot-rule.conflict.txt`，Toast 提示 8 秒后自动消失，正式词库继续使用。

打开提示的冲突文件，按顶部说明处理 `<<<<<<< 本机修改`、`=======`、`>>>>>>> 服务端修改`：选择一侧或自行编辑最终内容，删除所有标记后保存。程序通过保存/替换事件检查；格式有效时提交服务端。服务端确认持久保存、正式文件更新成功后，冲突文件永久删除。顶部自动生成的说明不会进入正式词库；用户自己的注释保留。再次产生冲突或网络失败时保留文件。

`logs/hotword_sync/` 保存同步基线和待处理冲突，应随程序保留，不要当普通日志清理。每个曾连接的服务端只保存一份必要基线，没有持续累积的全文同步历史。切换服务端后会与它的现有状态合并；两台一直运行的服务端不会在后台定时互相同步，远端最新内容在下次启动或正常退出时交换。
