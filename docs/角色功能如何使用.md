# 角色功能如何使用

## 什么是角色

角色是客户端的 LLM（大语言模型）后处理功能：识别结果的开头命中某个角色名时，把这句话交给该角色，调用 LLM 的 API 润色、翻译或当作语音助手回答。

每个角色有自己的提示词、模型和输出方式：

- **typing**：模拟键盘把结果打进当前光标处，适合润色
- **toast**：在屏幕上弹窗显示（支持 Markdown），适合问答、翻译；本机运行 OpenMate 桌面看板时改由看板展示

例如先用鼠标选中一段文字，再说「助理，解释一下这段」：客户端检测到「助理」前缀，读取选中的文字，一起发给 LLM，回答以弹窗显示。

使用前需要在角色文件里配好 LLM API：可以用在线服务（如 DeepSeek），也可以用本地模型（LM Studio、Ollama）。

---

## 一、角色文件在哪

角色文件在项目根目录的 [LLM/](../LLM/) 文件夹，每个 `.py` 文件定义**一个角色**。启动时加载该目录下所有角色文件，修改后**自动热重载**（3 秒防抖，保留各角色的对话历史）。

另有两个不是角色的文件：`backends.py`（后端切换，见第九节）和 `secrets.py`（API 密钥，未被 git 跟踪，由你自己维护）。

### 内置角色

| 文件名 | 触发前缀 | 输出模式 | 用途 |
|--------|---------|---------|------|
| [default.py](../LLM/default.py) | （默认，无前缀） | typing | 默认角色，用于润色，已关闭 |
| [助理.py](../LLM/助理.py) | 助理 | toast | 日常与知识问答，一至三句纯文本直接作答；联网搜索、可看图 |
| [翻译.py](../LLM/翻译.py) | 翻译 | toast | 有选中文字时翻译选中内容、语音只当要求；没选中时翻译语音本身。当前已关闭 |
| [雾切响子.py](../LLM/雾切响子.py) | 雾切响子 / 雾切妹妹 | toast | 人设角色，在 OpenMate 上按行分条展示 |
| [新岛真.py](../LLM/新岛真.py) | 新岛真 / 真学姐 | toast | 人设角色，在 OpenMate 上按行分条展示 |

## 二、角色文件格式

角色文件是普通的 Python 文件，用顶层变量配置。以下是一个最小示例（没写的字段取默认值）：

```python
# ===== 基本信息 =====
name = '翻译 | translate'      # 角色名称，| 分隔多个触发前缀，留空表示默认角色
enabled = True                  # 是否启用此角色

# ===== API 配置 =====
provider = 'lmstudio'           # API 提供商，见下表
api_url = ''                    # 留空则使用 provider 对应的默认地址
api_key = ''                    # API Key（建议写在 LLM/secrets.py 里再 import）
model = 'local-model'           # 模型名称

# ===== 上下文与功能 =====
max_context_length = 4096       # 对话历史容量（估算 token）
enable_hotwords = True          # 是否把热词列表放进上下文
enable_history = True           # 是否保留对话历史
enable_read_selection = True    # 是否读取选中文字（读取方式见第八节）
selection_max_length = 1024     # 选中文字最大长度

# ===== 输出 =====
output_mode = 'toast'           # 'typing' 直接打字 | 'toast' 弹窗

# ===== 生成参数 =====
temperature = 0.7
top_p = 0.9
max_tokens = 4096

# ===== System Prompt（核心！） =====
system_prompt = '''
你是一个翻译助手。将用户输入的内容翻译成中文。
如果输入是中文，就翻译成英文。
只输出翻译结果，不要解释。
'''
```

完整字段与默认值见 [core/client/llm/llm_role_config.py](../core/client/llm/llm_role_config.py)，常用字段见本文末尾的「字段速查」。

## 三、核心字段说明

### name
- 触发前缀，识别结果以它开头时触发该角色；`|` 分隔多个别名，第一个是显示名
- 不同角色的显示名不能相同：重名时只有文件名排在后面的那个生效，终端会给出一行警告
- 留空表示默认角色（所有没匹配到前缀的语音都归它）

### enabled
- `True`：角色生效
- `False`：前缀角色不再参与匹配；默认角色则不再处理，识别结果直接输出

### output_mode
- `'typing'`：模拟键盘逐字打字输出（`config_client.py` 的 `paste = True` 时改为生成完再粘贴）
- `'toast'`：弹窗显示，支持 Markdown 渲染

### provider

| provider | 说明 | 默认 API 地址 |
|----------|------|-------------|
| `ollama` | 本地 Ollama | `http://127.0.0.1:11434` |
| `lmstudio` | 本地 LM Studio | `http://127.0.0.1:1234/v1` |
| `openai` | OpenAI | `https://api.openai.com/v1` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` |
| `moonshot` | 月之暗面 | `https://api.moonshot.cn/v1` |
| `zhipu` | 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` |
| `volcengine` | 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` |
| `cerebras` | Cerebras | `https://api.cerebras.ai/v1` |

其他 OpenAI 兼容服务可任选一个 provider 并手动填写 `api_url`。不写 `request_timeout` 时超时只有 2 秒，联网搜索、看图或较慢的网关都必须调大（内置角色都是 60 秒）。

1. 在 `LLM/` 目录下新建一个 `.py` 文件，文件名建议用中文（如 `代码助手.py`）；也可以复制已有角色文件再改
2. 按上面的格式定义变量
3. 保存即自动加载，无需重启

## 五、触发机制

```
语音识别结果 → 角色检测
    ↓
遍历所有启用（enabled = True）的角色
    ↓
检查文本是否以 name 里的某个名字开头
    ├─ 匹配成功 → 去掉前缀和紧跟的「：，。,. 」→ 交给该角色处理
    └─ 全部不匹配 → 检查默认角色的 enabled
        ├─ True → 交给默认角色处理
        └─ False → 不调用 LLM，直接输出
```

处于连续对话中时（第十节）不做前缀检测，整句直接发给当前角色。对具名角色说「几点提醒我做什么」会先走一次性提醒，见 [提醒功能如何使用](提醒功能如何使用.md)。

## 六、输出模式说明

### Typing 模式

- 边生成边模拟键盘打字；`paste = True` 时先完整生成再通过剪贴板粘贴
- 生成过程中按 `Esc`（`config_client.py` 的 `llm_stop_key`）停止输出

### Toast 模式

- 弹窗出现时先显示「正在思考…」，联网检索时换成「正在联网搜索…」，回复的第一个字到达后由回复取代
- 弹窗从最小宽度起随内容变宽、到最大宽度后换行；内置角色统一采用屏幕宽度的 30%～50%（两个 `_px` 值均为 `0`）。自定义时可设置 `toast_min_width_px` / `toast_max_width_px`（正数像素值优先）或对应的 `_ratio`（屏幕宽度比例）
- 可自定义字体、字号、颜色、背景、透明度、圆角
- 生成完成后按字数自动决定停留时长：`toast_duration` 是最短停留时间，字越多停得越久，最长 30 秒；鼠标悬停不会延长，到期时鼠标还在弹窗上则移开后关闭
- 拖动过的弹窗不再自动关闭；新的角色回复出现时，旧弹窗会被替换
- 顶部空白处可拖动；选中文字后 `Ctrl+C` 复制选中部分，没选中则复制全文
- 每个新弹窗都要先鼠标点击（正文或顶部空白均可），焦点仍在该窗口内时 `Esc` 才有效；切到其他软件按 `Esc` 不影响本地角色回复
- 生成中按 `Esc`（包括「正在思考…」和联网搜索期间）会立即关窗、结束本地等待，控制台显示「已取消」，可以继续下一次提问；即使已显示半截回答，也整轮放弃，不写角色记忆或角色对话 Markdown、不自动回车。录音和识别原文的日记仍按原配置保存，连续对话仍跟随录音时的切换操作，本轮图片照常消耗
- 回复生成完成后按 `Esc` 只关闭窗口，已经完成的回答和记忆保留；单击不改变自动关闭规则，真正拖动才会让弹窗常驻
- 本地取消后，后台网络请求可能仍需等待返回或超时，迟到内容会被丢弃；模型正常结束却没有正文时，仍显示黄色「（空回复，详见日志）」

**OpenMate 桌面看板接管**：本机的 OpenMate 以 external 模式运行时（默认 `http://127.0.0.1:18760`），toast 角色的输出自动转交 OpenMate 展示，不再弹本地窗口。客户端会获取看板当前角色的情绪状态列表，让模型在回复里插入 `<state:情绪ID>` 标签驱动立绘（标签不会显示在正文里，本地弹窗和打字输出也会去掉它）。OpenMate 退出后下一句自动恢复本地弹窗；中途失败则用本地弹窗补上结果。确认接管后，本地的「正在处理结果」悬浮提示改由 OpenMate 的「正在输入」动画代替。相关配置见 `config_client.py` 的 `openmate_*`；角色文件可用 `openmate_enabled = False` 单独禁用，用 `openmate_character` 指定看板上的角色。

**回复分段**（仅 OpenMate 展示时生效）：`enable_result_splitter = True` 后，回复按 `result_split_delimiter`（默认两个换行 `\n\n`）切成多条消息逐条展示，第一条生成完就开始展示。空段丢弃，只含情绪标签的段并入下一段。本地对话历史与 `年/月/日-角色.md` 记录仍保存完整原文；未连接 OpenMate 时回退为完整显示。雾切响子、新岛真按单个换行 `\n` 切分。

## 七、上下文构成

启用相关功能时，发给 LLM 的消息结构如下：

```
System: （角色的 system_prompt；走 OpenMate 时末尾追加情绪标签说明）

（对话历史，多轮问答记录）            ← enable_history

当前时间：2026-07-31 15:04 星期五       ← enable_datetime

热词列表：[Claude, CapsWriter, ...]    ← enable_hotwords

选中文字：被选中的文本内容              ← enable_read_selection

用户输入：用户本次语音输入的内容（带图时附上图片）
```

历史超过 `max_context_length` 的 80% 时从最旧的消息开始丢弃。历史里只保留最近一张图片，更早的图显示为 `［图片］`。

**记忆在重启后保留**：每轮对话结束就保存到 `logs/llm_memory/`，每个角色一个文件，按角色 `.py` 文件名命名（改 `name` 不影响，改文件名则从空记忆开始）。启动时自动读回，终端的「LLM 角色」表里会在该角色那一行写「已恢复 N 轮对话」；文件读不了时写「恢复失败：原因」，原文件改名保留（如 `雾切响子.bad-20261003-154500.json`），该角色从空记忆开始。另外几点：

- 记忆不会过期，要从零开始就用托盘菜单「清除记忆」：清空所有角色的记忆，并删除 `logs/llm_memory/` 下的全部文件。`年/月/日-角色.md` 对话记录不受影响。
- 回复为空的一轮不写入记忆。本地 Toast 取消按第六节整轮放弃；OpenMate / typing 中断时仍保留已输出的部分。
- 保存时图片只留占位符：重启前模型能看到最近那张图，重启后只知道那里有过一张图。
- 关掉 `enable_history` 或删掉角色文件时，记忆文件留着不动，重新开启或恢复文件后会再读回来。

## 八、读取选中文字

角色开启 `enable_read_selection` 后，每次请求读取一次当前选区，成功时控制台在「识别结果」上方显示一行「选中文本」预览。读取方式由 `config_client.py` 的 `selection_mode` 统一决定：

| 取值 | 行为 |
|---|---|
| `'uia'` | 只用只读接口（Windows UI Automation，Scintilla 编辑器另有专门查询），不发按键、不动剪贴板；读不到就不附加 |
| `'uia_then_ctrl_c'` | 先只读获取，没取到文字再模拟 Ctrl+C；遇到密码框或焦点已变化时不复制 |
| `'ctrl_c'` | 直接模拟 Ctrl+C 复制 |

注意：

- 后两种方式会发送 Ctrl+C，在终端里可能中断正在运行的程序；复制还会覆盖剪贴板里的图片
- VS Code 编辑区需要打开「Editor: Accessibility Support」（`editor.accessibilitySupport`）才能被只读接口读到
- VS Code 集成终端和部分 TUI 程序里的高亮，只读接口读不到
- 同一段文字已经在对话历史里时，本轮不重复附加（预览上会注明）；清除记忆后可以再次附加

## 九、切换后端（DeepSeek / CPA 网关）

内置 toast 角色的 API 配置写成一行：

```python
backend = 'deepseek'    # 或 'cpa'
```

模型、地址、请求格式、超时由 `LLM/backends.py` 按名字给出：`'deepseek'` 直连 DeepSeek，`'cpa'` 走局域网里的 CPA 网关（换网关上的模型改 `backends.py` 的 `CPA_MODEL`）。存盘即生效。网关只在局域网内可达，不在网里时走 `cpa` 的角色会直接报错，不会自动改用 DeepSeek。

## 十、连续对话

录音期间按一下 `config_client.py` 的 `continuous_chat_key`（默认空格）：如果这句话触发了具名角色，就进入与该角色的连续对话，之后每句话不用再念角色名、直接发给它。连续对话中录音时再按一次则退出。

- 录音悬浮框的底色表示状态：浅黄 = 这次录音正在进入或退出，浅绿 = 已在连续对话中
- 同一次录音里按两次等于没按；短按取消或按 Esc 打断的录音，其中的切换也一并作废
- 闲置超过 `continuous_chat_timeout`（默认 300 秒）后，下次按录音键时自动退出
- 只改「发给谁」，不影响各角色自己的对话历史

## 十一、截图提问（视觉输入）

先用系统截图工具（如 Win+Shift+S）把图放进剪贴板，再按 `vision_capture_key`（默认 `Ctrl+Alt+D`），图片会随**下一句话**发给角色：

- 终端会提示「已挂载图片 …」或未挂载的原因；挂着图的那次录音，悬浮框内侧多一圈描边
- 只接受 `vision_clipboard_max_age`（默认 60 秒）内放进剪贴板的图；客户端启动后剪贴板没变过时，需要重新复制一次
- 下一次有效录音无论是否用上，图都会消失：命中开启 `enable_vision = True` 的角色就上传，否则丢弃并在终端说明；短按取消或 Esc 打断的录音不消耗图片
- 开启 `enable_vision` 的角色要同时把 `model` 换成支持视觉的模型
- 挂载过的图存进 `logs/vision/`（最多 `vision_archive_keep` 张），便于事后核对

## 十二、联网搜索

角色设置 `enable_web_search = True` 后，由模型自行判断是否需要联网检索（使用服务商内置的 `web_search` 工具，本地不需要搜索 API Key）。检索时弹窗先显示「正在联网搜索…」，控制台结果行标成 `模型结果[助理(搜索)]`。用 `backend` 的角色不用另外配置：DeepSeek 走它的 Anthropic 兼容接口（它的 Responses API 不执行搜索），CPA 网关走 Responses API。自己写 `api_url` 的角色，后端要么支持 Anthropic 格式的 `web_search_20250305`（`api_format = 'anthropic'`），要么支持 Responses API 的内置 `web_search`，并设置足够的 `request_timeout`。`enable_datetime = True` 会在每句话里附上当前时间，帮模型判断知识是否过期。


## 十四、实用技巧

### 1. 开启润色

如果希望所有语音都经过 LLM 润色，把 `default.py` 中的 `enabled = False` 改为 `True`。不过 LLM 处理会增加延迟，服务端的 Qwen3-ASR 加上热词功能，多数情况下已经不需要润色。

### 2. 多别名触发

```python
name = '翻译 | translate'
```

ASR 常把某个角色名识别错时，把错的写法也加成别名。

### 3. 角色特定热词

角色 `enable_hotwords = True` 时，客户端会把音素匹配到的潜在热词列表放进上下文，帮助 LLM 理解专业术语。

## 十五、常见问题

**Q: 修改角色文件后需要重启吗？**

不需要。系统会自动检测 `LLM/` 目录变化，3 秒后自动重载，已有对话历史保留。改 `config_client.py` 则需要重启客户端。

**Q: 为什么说了前缀但没有触发角色？**

检查以下几点：
- `config_client.py` 中 `llm_enabled = True`
- 角色文件中 `enabled = True`，且文件没有语法错误（出错的角色不会被加载）
- 前缀是否完全匹配（区分中英文）；识别常出错时加别名
- 查看日志 `logs/client_latest.log`

**Q: 如何暂时禁用一个角色？**

将角色文件中的 `enabled = False`，保存后自动生效。

**Q: 回复一闪而过、弹窗是空的？**

控制台会显示「（空回复，详见日志）」，原因（被截断、拒答、出错）在 `logs/client_latest.log` 里紧挨着的 WARNING 中。

## 附：字段速查

| 字段 | 作用 |
|---|---|
| `name` / `enabled` | 触发前缀（用竖线分隔别名）/ 是否启用 |
| `provider` / `api_url` / `api_key` / `model` | 请求发给谁；内置 toast 角色改由 `backend` + `resolve()` 给出 |
| `api_format` | 请求格式：`'openai'`（默认，Chat Completions / Responses）或 `'anthropic'`（`api_url` 写到 `/v1` 之前）；内置角色由 `backend` 给出 |
| `request_timeout` | 单次请求超时（秒），0 表示用 provider 默认的 2 秒 |
| `max_context_length` | 对话历史容量（估算 token），超过 80% 从旧裁剪；不是模型的上下文窗口 |
| `enable_history` | 多轮记忆（保存在 `logs/llm_memory/`，重启后恢复，托盘「清除记忆」可清） |
| `enable_hotwords` | 把潜在热词列表放进上下文 |
| `enable_read_selection` / `selection_max_length` | 读取选中文字 / 最大长度 |
| `enable_vision` | 接收截图；不检查模型是否真支持视觉，写错了服务端返回 400 |
| `enable_web_search` / `enable_datetime` | 联网搜索 / 注入当前时间 |
| `enable_thinking` | 思考模式：关闭时直接回答、更快；Ollama 与 DeepSeek 生效，其他后端看服务商是否支持 |
| `output_mode` | `typing` 或 `toast` |
| `toast_*` | 弹窗宽度（`_min/_max_width_px`、`_ratio`）、`toast_initial_height`（0 为自动）、字体、字号、颜色、背景、`toast_duration`（最短停留毫秒）、`toast_editable`、`toast_window_alpha`、`toast_corner_radius`；只影响本地弹窗 |
| `openmate_enabled` / `openmate_character` | 是否允许 OpenMate 接管 / 看板上的角色 ID（留空跟随全局配置或看板当前角色） |
| `enable_result_splitter` / `result_split_delimiter` | OpenMate 分段展示 / 分隔符 |
| `temperature` / `top_p` / `max_tokens` / `stop` | 生成参数；`max_tokens` 是单次回复上限，开启思考或走 Responses API 时推理内容也会占用它 |
| `extra_options` | 额外 API 参数的透传 |
| `prompt_prefix_*` | 上下文里各段的标签文字（热词、选中文字、当前时间、用户输入） |
| `system_prompt` | 角色人设，决定模型「是谁、怎么答」 |
