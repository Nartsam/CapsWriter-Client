# 角色功能如何使用

## 什么是角色

角色系统是 CapsWriter-Offline 的 LLM （大语言模型） 后处理功能，可以调用 LLM 的 API 对识别结果进行润色，或当作语音助手进行对话。

你可以定义多个「角色」，每个角色有自己的提示词、模型、输出方式。语音识别完成后，通过**前缀匹配**触发对应角色进行处理。

角色有两种输出方式：

- 打字输出，可用作润色
- Toast 弹窗输出，可用作语音助手

比如你用鼠标选中一段文字，然后说：

```
翻译这段文字
```

客户端检测到"翻译"前缀，自动调用对应的 LLM 角色，复制所选文字，调用 LLM API，返回的结果会以 Toast 弹窗显示。

使用角色前，需要编辑角色文件，配置 LLM API，可以用在线服务如 DeepSeek，也可以用本地模型如 LM Studio 或 Ollama。

---

## 一、角色文件在哪

角色文件存放在项目根目录的 [LLM/](../LLM/) 文件夹中，每个 `.py` 文件定义**一个角色**。系统启动时会自动加载该目录下所有角色文件，修改后**自动热重载**（3 秒防抖）。

### 内置角色

| 文件名 | 触发前缀 | 输出模式 | 用途 |
|--------|---------|---------|------|
| [default.py](../LLM/default.py) | （默认） | typing | 默认角色，用于润色，已经关闭 |
| [翻译.py](../LLM/翻译.py) | 翻译 | toast | 翻译选中文字 |
| [助理.py](../LLM/助理.py) | 助理 | toast | 问答助手 |

## 二、角色文件格式

角色文件是普通的 Python 文件，通过定义顶层变量来配置角色。以下是一个完整示例：

```python
# ===== 基本信息 =====
name = '翻译 | translate'      # 角色名称，| 分隔多个触发前缀，留空表示默认角色
enabled = True                  # 是否启用此角色

# ===== API 配置 =====
provider = 'lmstudio'           # API 提供商：'lmstudio', 'ollama', 'openai', 'deepseek', 'moonshot', 'zhipu', 'volcengine', 'cerebras'
api_url = ''                    # 留空则自动使用 provider 对应的默认值
api_key = ''                    # API Key
model = 'local-model'           # 模型名称

# ===== 上下文管理 =====
max_context_length = 4096       # 最大上下文长度（token）

# ===== 功能开关 =====
enable_hotwords = True          # 是否将热词列表放入上下文
enable_history = True           # 是否保留对话历史
enable_read_selection = True    # 是否读取选中文字（模拟 Ctrl+C）
selection_max_length = 1024     # 选中文字最大长度

# ===== 输出配置 =====
output_mode = 'toast'           # 'typing' 直接打字 | 'toast' 弹窗

# ===== Toast 外观（仅 toast 模式） =====
toast_font_size = 23
toast_font_color = 'white'
toast_bg_color = '#075077'
toast_duration = 3000           # 显示时长（毫秒）

# ===== 生成参数 =====
temperature = 0.7
top_p = 0.9
max_tokens = 4096

# ===== 提示词定制 =====
prompt_prefix_hotwords = '热词列表：'
prompt_prefix_selection = '选中文字：'
prompt_prefix_input = '用户输入：'

# ===== System Prompt（核心！） =====
system_prompt = '''
你是一个翻译助手。将用户输入的内容翻译成中文。
如果输入是中文，就翻译成英文。
只输出翻译结果，不要解释。
'''
```

## 三、核心字段说明

### name
- 触发前缀，语音识别结果以此开头时触发该角色
- 支持 `|` 分隔多个别名，如 `'翻译 | translate'`
- 留空表示默认角色

### enabled
- `True`：角色生效
- `False`：前缀角色不再参与匹配；默认角色则不再处理，识别结果直接输出

### output_mode
- `'typing'`：模拟键盘逐字打字输出，用于润色
- `'toast'`：在 Toast 浮动窗口中显示（支持 Markdown 渲染），适合翻译、问答等

### provider
支持的服务商：

| provider | 说明 | 默认 API 地址 |
|----------|------|-------------|
| `ollama` | 本地 Ollama | `http://127.0.0.1:11434` |
| `lmstudio` | 本地 LM Studio | `http://127.0.0.1:1234/v1` |
| `openai` | OpenAI | `https://api.openai.com/v1` |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` |
| `moonshot` | 月之暗面 | `https://api.moonshot.cn/v1` |
| `zhipu` | 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` |
| `volcengine` | 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` |
| `cerebras` | Cerebras | `https://api.cerebras.ai/v1` |

其他 OpenAI 兼容服务可任选一个 provider 并手动填写 `api_url`。

## 四、如何创建新角色

1. 在 `LLM/` 目录下新建一个 `.py` 文件，文件名建议用中文（如 `代码助手.py`）
2. 按照上面的格式定义变量
3. 保存文件，**自动加载**，无需重启

或者直接从已有角色文件复制一份新的，然后修改即可。

其实无需使用多个角色，当前内置的可用角色主要是：

- 助理，是用的 DeepSeek 的 API
- 翻译，用于翻译选中文字或语音输入

## 五、触发机制详述

检测流程：

```
语音识别结果 → 角色检测器
    ↓
遍历所有启用（enabled = True）的角色
    ↓
检查 text 是否以 role.names 之一开头
    ├─ 匹配成功 → 去掉前缀和分隔符 → 交给该角色处理
    └─ 全部不匹配 → 检查默认角色的 enabled
        ├─ True → 交给默认角色处理
        └─ False → 不调用 LLM，直接输出
```

**分隔符清除**：匹配到前缀后，自动去掉紧跟的 `：、，。,. ` 等字符。

## 六、输出模式说明

### Typing 模式（`'typing'`）

- 边生成边模拟键盘打字
- 如果 `config_client.py` 中 `paste = True`，则先完整生成再通过剪贴板粘贴
- 按 `Esc` 可中断输出（由 `llm_stop_key` 配置）

### Toast 模式（`'toast'`）

- 在屏幕上的浮动窗口中显示
- **支持 Markdown 渲染**（标题、代码块、列表等）
- 可自定义字体、颜色、背景、显示时长
- 鼠标可左键拖拽，右键复制内容，鼠标离开 3 秒后自动关闭
- 键盘 ESC 可手动关闭

**OpenMate 桌面看板接管**：如果本机的 OpenMate 以 external 模式运行（默认 `http://127.0.0.1:18760`），toast 角色的输出会自动转交 OpenMate 展示，本地弹窗不再出现。客户端会自动获取角色的情绪状态列表，让 LLM 在回复中插入 `<state:情绪ID>` 标签驱动立绘切换（标签不会显示在正文里）。OpenMate 退出后下一句自动恢复本地弹窗，无需重启客户端。确认接管后，本地的「正在处理结果」悬浮提示也会隐藏，改由 OpenMate 对话框显示「正在输入」动画，直到回复的第一条内容出现。相关配置见 `config_client.py` 的 `openmate_*` 项；角色文件可用 `openmate_enabled = False` 单独禁用。

**回复分段**（仅 OpenMate 展示时生效）：角色文件设置 `enable_result_splitter = True` 后，回复会按 `result_split_delimiter`（默认两个换行 `\n\n`）切成多条消息，在 OpenMate 上逐条展示、按字数节奏停留，模仿人类连发多条 IM 消息；段落首尾空白会去除，空段丢弃。第一条消息生成完即开始展示，不等全文。切分只影响 OpenMate 展示：本地对话历史与 `年/月/日期-角色.md` 日志仍保存完整原文，未连接 OpenMate 时回退普通完整显示。内置的「雾切响子」「新岛真」两个角色已开启（按单个换行 `\n` 切分，与人设的逐行短消息风格配合）。

## 七、上下文构成

当角色启用相关功能时，LLM 接收到的消息结构如下：

```
System: （角色的 system_prompt）

（对话历史，多轮问答记录）

热词列表：[Claude, CapsWriter, ...]    ← enable_hotwords

选中文字：被选中的文本内容              ← enable_read_selection

用户输入：用户本次语音输入的内容         ← prompt_prefix_input
```

## 九、实用技巧

### 1. 开启润色

如果你希望所有语音都经过 LLM 润色，将 `default.py` 中的 `enabled = False` 改为 `enabled = True`。

其实，Qwen3-ASR 已经非常强大，加上热词功能，已经完全不需要 LLM 润色功能。毕竟 LLM 处理会增加延迟，降低体验。

在作者的 RTX5050 独显笔记本上，Qwen3-ASR 的短音频延迟最短只有 110ms，体感上是瞬出，识别率又非常好。如果开启润色，每次输出都加上 0.3s 的延迟，体感上就会慢一拍。

只不过 Typeless 有润色，LLM 又这么火，总会有朋友想试试。作者自己试用了 Typeless，表示延迟太大，体验不合格。

### 2. 多别名触发

```python
name = '翻译 | translate'
```

### 3. 角色特定热词

如果某个角色 `enable_hotwords = True`，客户端会将 RAG 检索到的潜在热词列表放入 LLM 上下文，帮助 LLM 理解专业术语。

### 4. 结合选中文字

对于翻译、改写等场景，设置 `enable_read_selection = True`，先选中文字再语音说出指令，LLM 可以同时拿到选中内容和语音输入。

## 十、常见问题

**Q: 修改角色文件后需要重启吗？**

不需要。系统会自动检测 `LLM/` 目录变化，3 秒内自动重载。

**Q: 为什么说了前缀但没有触发角色？**

检查以下几点：
- `config_client.py` 中 `llm_enabled = True`
- 角色文件中 `enabled = True`
- 前缀是否完全匹配（区分中英文）
- 查看日志 `logs/client_latest.log` 中的角色检测信息

**Q: 如何暂时禁用一个角色？**

将角色文件中的 `enabled = False`，保存后自动生效。

**Q: 对话历史会一直累积吗？**

不会。当历史消息的估算 token 总数超过 `max_context_length` 的 80% 时，会自动从最旧的消息开始丢弃。


```
附录：以“助理”为例，说明配置文件中每个配置项的作用

基本信息
name = '助理' — 触发前缀。语音识别结果以「助理」开头时就交给这个角色，前缀和紧跟的标点会被去掉，剩余部分作为真正的输入。支持 | 分隔多个别名（如 '助理 | assistant'）。留空则是默认角色（所有没匹配到前缀的语音都归它）。
enabled = True — 角色总开关。False 时角色检测直接跳过它，说「助理 xxx」不会触发。
API 配置 — 决定请求发给谁
provider = 'deepseek' — 服务商，决定默认 API 地址和协议细节。
api_url — 留空则用 provider 的默认地址（DeepSeek 是 https://api.deepseek.com）；填了就覆盖，比如指向自建代理。
api_key — 鉴权密钥，这里从 LLM/secrets.py 导入，避免密钥直接写在角色文件里。
model — 模型名，原样传给 API。
上下文管理
max_context_length = 1024 * 1024 — 对话历史的容量上限（估算 token 数）。历史累积超过它的 80% 时，从最旧的消息开始丢弃。助理设成 1M 实际意味着「几乎永不裁剪」，只受 DeepSeek 模型本身上下文窗口的限制——如果对话真攒到超过模型窗口，API 会报错，这个值并不能防住那种情况。
功能配置 — 决定每次请求里塞什么内容
enable_hotwords = False — 开了会把本次识别 RAG 匹配到的热词列表放进提示词，帮模型认专业术语。助理是问答场景用不上，所以关了。
enable_thinking = False — 思考模式，仅 Ollama 本地模型生效，对 DeepSeek 无作用。
enable_history = True — 多轮记忆开关。开着时每次请求都带上之前的问答历史（内存存储，重启清空，托盘菜单可清除）。
enable_read_selection = True — 触发角色时模拟 Ctrl+C 读取你当前选中的文字，作为「选中文字：」段落塞进提示词。效果是你可以选中一段内容后说「助理 解释一下这段」。
selection_max_length = 1000 — 选中文字超长时截断，防止把整篇文档塞进请求。
输出配置
output_mode = 'toast' — 结果显示方式。'toast' 是屏幕浮窗（支持 Markdown 渲染），'typing' 是模拟键盘把结果打进当前光标处。这个选择还决定了 OpenMate 接管是否可能发生——只有 toast 模式才会探测 OpenMate。
Toast 弹窗配置 — 只影响本地浮窗外观
toast_initial_width = 0.5（占屏幕宽度一半）、toast_initial_height = 0（按内容自动算高）、字体/字号/颜色/背景色、toast_duration = 3000（生成完毕后鼠标不碰它 3 秒自动关闭）、toast_editable = True（渲染后的文本可以直接编辑复制）、toast_window_alpha = 0.92（半透明）、toast_corner_radius = 12（圆角）。

注意两点：输出转交 OpenMate 展示时这组参数不生效（OpenMate 用自己的样式），但 OpenMate 中途失败回退本地弹窗时仍会用到；typing 模式下这组全部无效。

生成参数 — 原样传给 API，影响模型行为
temperature = 0.7 — 随机性，越高回答越发散。
top_p = 0.9 — 采样范围，与 temperature 配合控制多样性。
max_tokens = 4096 — 单次回复的输出上限，超过会被截断（不是上下文上限，别和 max_context_length 混淆）。
stop = '' — 停止序列，模型输出到该字符串就停，一般留空。
高级选项与提示词前缀
extra_options = {} — 额外 API 参数的透传通道，比如想加 frequency_penalty 就写在这里，不用改代码。
prompt_prefix_hotwords / _selection / _input — 提示词里三个段落的标签文字。最终发给模型的用户消息长这样：「热词列表：…（若开启）／选中文字：…（若开启且有选中）／用户输入：你说的话」。改这些只是改标签措辞。
System Prompt
system_prompt — 角色人设，整个角色最核心的部分，决定模型「是谁、怎么答」。助理的很简短（按要求输出、不加多余说明）。当输出转交 OpenMate 时，客户端会在它后面自动追加情绪标签指令，本地弹窗时则不追加。
文件里没写、但也可用的参数
openmate_enabled（默认 True）/ openmate_character（默认空）— 上次加的 OpenMate 接入项，助理.py 没写就用默认值：允许 OpenMate 接管、角色 ID 用全局配置。想让助理永远只用本地弹窗，加一行 openmate_enabled = False 即可。
```
