## 已知状态

- 录音键（`ctrl_r`）的按下事件被吞掉、松开时前台程序却能收到一个抬起事件——**符合设计，不是 bug**（2026-07-28 用键盘测试网站观察确认）。原始 KEYDOWN/KEYUP 都被 `suppress_event()` 拦下，但 `event_handler._release_suppressed_modifier()` 会额外补发一个合成释放事件。理由见 `key_mapper.py` MODIFIER_KEYS 上方注释：低级钩子的抑制并非总是可靠（例如焦点在提权窗口上时钩子收得到却拦不住），一旦 KEYDOWN 漏过去而 KEYUP 被吞，修饰键会卡在按下状态，之后每次按键都变成组合键。这是刻意的不对称取舍——修饰键的释放是幂等的，多发无害；卡住的按下会持续污染后续输入。ESC 打断键因为不是修饰键、卡不住状态，反而采用严格配对、不做补发。
  - 边界：若把录音键换成 **Alt**，孤立的 Alt 抬起会被不少 Win32 程序当作激活菜单栏的信号，需要单独处理。
  - 可选优化（暂不做，2026-07-28 用户确认）：补发前先用 `GetAsyncKeyState` 判断系统是否真认为该键还按着，只在确实卡住时补发，可消掉正常路径上的多余事件。但抑制状态下该 API 的返回值是否可靠需实机验证。

- ~~OpenMate 情绪立绘不切换~~（2026-07-16 验收发现，2026-07-17 已修复）：曾因 `openmate_character` 留空时按角色列表第一个取状态，注入了非当前角色（雾切响子）的状态 ID，标签全部失配回退默认立绘。OpenMate 侧新增 `GET /v1/presentation` 后，客户端改为留空时每次请求解析当前生效角色再取其状态，并把流固定到该角色，待实机复验。

- Toast 窗口构造异常会被 `ToastMessageManager._process_queue` 的 `except Exception` 吞掉，调用方只看到 `wait_for_window` 超时和「Toast 窗口创建失败」，看不出根因。2026-07-31 已给该 except 加 `exc_info=True`，但结构仍是「窗口构造失败 = 静默无弹窗」，改 `core/ui/toast_*.py` 后务必真的弹一次窗口验证，别只看有没有报错。（2026-07-31）

- Tk 几何字符串里负坐标必须写成 `+-100+50`：`wm geometry` 会把开头的 `+`/`-` 当作「从左/上边缘量」还是「从右/下边缘量」的标志位消费掉，符号后面的数字再单独按有符号数解析。所以 Python 的 `f"{x:+d}"` 对负数产出的 `-100+50` 会被理解成「窗口右边缘距屏幕右边缘 100px」，实测 1920 宽屏上 200px 宽的窗口会被摆到 x=1640。写位置一律用 `f"+{x}+{y}"`。（2026-07-31）

## 决策记录

- 角色 Toast 宽度配置彻底迁移为 `toast_min_width_px`/`toast_max_width_px` 与对应 ratio，不兼容旧 `toast_initial_width`：本项目为个人使用，不需要旧角色文件兼容层；像素值优先，非法时逐级回退比例和内置 320～800px，反向区间整体回退并警告，等宽区间允许用作固定宽度。（2026-07-28）
- 录音打断只改客户端，用「发 is_final 冲服务端缓冲 + 本地按 task_id 丢弃结果」实现：服务端跑在另一台机器上（地址见 `config_client.py` 的 `addr`），新增取消协议要跨机器维护并部署两份代码，收益只是省掉一次残余缓冲的推理，不成比例。断开重连虽然零推理浪费，但会把「取消一句话」和连接生命周期耦合，重连抖动会变成用户可见故障。（2026-07-28）
- 打断键与 `llm_stop_key` 拆成两个配置项：语义不同（作废输入 vs 停止输出并保留已输出内容），现在同为 esc 只是默认值巧合，复用会让改一个连带改另一个。（2026-07-28）
- 打断窗口截止到最终结果到达，不延伸到 LLM 生成阶段：那时文本很可能已经上屏到别的输入框，「丢弃」无法兑现；边界定为「结果到达前=作废，到达后=停止输出」。（2026-07-28）
- 打断键只在录音阶段拦截、等待结果阶段放行：录音状态由按键被按住这一物理事实兜底不会卡死，而等待状态依赖远程服务端回包，一旦不回，拦截会让该键全局失灵且极难排查。（2026-07-28）

- OpenMate 情绪标签使用稳定状态 ID，别名仅作提示词中的语义注解：ID 是 ASCII 稳定标识，规避 NFC 规范化和别名集合变动问题，OpenMate API 文档 §4.3 亦如此建议。（2026-07-16）
- OpenMate 接入采用无状态按需探测（每次 toast 请求前 GET /health，0.5s 超时），不维护长连接：OpenMate 可随时启停，无需重连逻辑；情绪状态列表缓存 5 分钟（失败缓存 1 分钟）。（2026-07-16）
- 不对 LLM 输出的情绪标签做本地校验：OpenMate 对无效状态回退默认立绘并剥离标签，本地增加跨分片流式校验层复杂度高且无用户可见收益。（2026-07-16）
- 本地定制的变更记录写本文件，不写 docs/CHANGELOG.md：后者是上游随版本发布的文件，混入本地条目会在升级覆盖时冲突。（2026-07-16）

## 本地定制变更（相对上游 Release）

- 2026-07-31：修复自适应宽度改造引入的三处问题。①`toast_base.py` 用了 `math.isfinite` 却没 `import math`，导致**每个 Toast 窗口构造都抛 NameError**、角色回复完全不弹窗（异常被 toast_manager 吞成一行 warning，现象只有「等待窗口超时」）；②`_set_geometry`/`_set_position` 用 `f"{x:+d}"` 拼几何字符串，负坐标语义被 Tk 反过来解释，窗口拖出左/上边界会跳到屏幕另一侧，改回 `f"+{x}+{y}"`；③`_grow_to_fit_text` 每个流式分片都对全文测量一次，退化成 O(n²)，加了「已到 max_width 就早退」并用其返回值省掉未增宽时多余的 `update_idletasks`。同时给 toast_manager 的 except 补 `exc_info=True`。
