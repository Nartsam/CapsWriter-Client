## 已知问题

- **DeepSeek 偶发空回复的根因未定**（2026-08-12）：任务 `49be29b3`（助理，第 4 轮，带选区的长问题）的流跑了 4.9s 没有一个 `output_text.delta`，最可能是输出额度在第一个可见 token 之前被推理耗尽。当时走 Responses API；2026-10-07 起 DeepSeek 改走 Anthropic 接口并真正关闭了思考，可能不再出现。再复现时把日志里的事件计数补到这里。
- **CPA 网关上游间歇性成片失败**（2026-09-05）：`...: EOF`、`503 auth_unavailable` 等，几条路径会同时挂、几分钟后又好；小样本看不出哪个模型更稳。请求重试策略见下方「普通角色请求保留有限重试」。
- **经 CPA 的 Gemini 回复攒齐了才发**（2026-09-05，2026-10-07 复测）：响应头要等生成完才到，之后所有事件一次性到达（网关修好搜索后实测：短问答 3～7s、搜索 7～13s）。Toast 没有打字机效果；`web_search_call` 事件虽已透传，但与正文同时到达，「正在联网搜索…」刚出现就被正文取代，等待期间显示的是「正在思考…」。智能时长从生成完成起算，不受影响。
- **待挂槽里的陈图**（2026-09-12）：时效检查只管剪贴板有多新，管不到图在待挂槽里躺了多久——被打断退回待挂的旧图会在下一次有效录音时照常发出，描边也看不出是哪张。若再出现，可考虑待挂超过 `vision_clipboard_max_age` 时给描边换色。
- **选区只读获取的盲区**（2026-09-15）：VS Code 普通编辑区要开 `editor.accessibilitySupport` 才读得到（未开时 UIA 返回空）；VS Code 集成终端（xterm.js 内部选区）与部分 TUI 的高亮读不到，只能用复制模式。按便携性约束，不做装扩展、改外部设置之类的方案。
- **OpenMate 的双屏全屏判定**（2026-09-07，外部项目）：OpenMate 的 `shouldDeferReminderForFullscreen()` 末尾仍把全局 `notificationState`（D3D/演示模式，不带显示器归属）当独立触发条件，前台已切到副屏的非全屏文档时仍可能延后提醒。应只改这个提醒判定函数：按前台窗口所在显示器判定，去掉全局状态这条触发。
## 仍然有效的决策

- **DeepSeek 走 Anthropic 兼容接口**（2026-10-07）：DeepSeek 的 Responses API 忽略 `web_search`（官方文档的工具支持表），flash 会把工具调用当正文吐出（DSML 标记、`<tool_result>`、整段 Python 代码），Toast 也就不再显示搜索状态；`thinking: disabled` 在 Responses 上同样无效，每次都先推理。`deepseek-v4-pro` 在 Responses 上还能搜，但不在文档内，单价约为 flash 的 3～4 倍，没有采用。Anthropic 接口（`/anthropic/v1/messages` + `web_search_20250305`）上 flash 能搜，关闭思考也生效：短问答首字中位约 0.6s（原 1.1s），搜索时 0.5～1.2s 出现搜索状态、约 1.9s 出首字。角色保持关闭思考（用户决定，觉得回答变差再打开 `enable_thinking`，首字约慢 0.3s）；提醒分析不跟着角色关思考，原因见 `reminder/analyzer.py`。
- **流式上屏在服务端切句、前缀续写，已上屏的字不回改**（2026-10-01）：客户端按停顿切句、逐句独立识别时，用字差异从 0.6% 升到约 2.6%，句间标点全变句号；带前一句音频再按文字去重又会吞字。改成服务端带前几句的音频和已出文字做前缀续写后，差异降到约 1.5%～2%，与标准答案的错字率和整段识别相当。每句末尾几个字暂缓上屏、由下一句重新识别（回滚）的做法实测更差，没有采用。实验数据与参数取舍见服务端 `connection/pause_splitter.py`、`worker/streaming.py` 的文件头。
- **后端切换分两层**（2026-09-05）：角色文件选后端，`LLM/backends.py` 选模型、地址与超时。角色文件是配置面，一眼能看出走哪个后端；后端细节只写一处，改端口或令牌时不会漏掉某个角色、让它静默连不上。
- **普通角色请求保留有限重试**（2026-10-07）：OpenAI 格式沿用 SDK 默认策略，连接错误、超时及部分 HTTP 错误最多重试 2 次；Anthropic 格式对连接错误及 HTTP 408/409/429/5xx 最多重试 2 次，依次等待 0.5s、1s，本地请求超时不重试。两条流式路径在开始读取成功响应的正文后均不重发；提醒分析的 OpenAI / Anthropic 请求显式设置 `max_retries=0`。
- **后端不自动回退或使用多候选**（2026-09-05）：`RoleConfig` 在加载期定死，运行时切后端要改 `llm_handler`/`llm_processor` 这条「漏转发不报错」的路径；网关只在局域网可达，人不在网里时是超时而不是拒绝，自动回退会让每句话先白等几秒。失败由诊断日志如实报出。
- **后端能力缺口不在客户端开特例**（2026-09-05）：两套后端的角色配置保持一致（CPA 下同样开 `enable_web_search`），网关缺什么在网关侧补。
- **测试按源码抽方法运行的方式暂不改**（2026-10-03）：`test_stream_output`、`test_selection`、`test_shortcut_keys`、`test_reminders` 用 `ast` 抽出被测方法，配一张手写的名字表运行（系统 Python 缺依赖，无法直接导入）。被测方法新用到模块级名字或 `self` 的新属性时，测试会报 `NameError`/`AttributeError`，要去补表。根治办法是公共加载工具：整个文件照常加载，缺的依赖自动换成替身。代价是替身会掩盖新依赖的真实行为、`self` 替身仍要手写、四个文件都要改；等补表变得频繁或要大改这几个测试时再做。
- **角色分段过多靠改提示词解决**（2026-09-13）：雾切响子、新岛真的简单回复以一条完整消息为主（50 字只作简洁参考，不再是拆条阈值），保留短句、语气和新岛真受惊/害羞时的短句连发；温度、后端、分隔符、发送器与已有历史都没改。没改成双换行分隔：DeepSeek 本来就常在短句之间输出双换行。
