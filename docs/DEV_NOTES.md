## 已知问题

- **空回复也写进对话历史**（2026-08-12）：`llm_processor._stream_request` 不论正文是否为空都写入本轮，之后每轮请求都会带一条空的 assistant 消息。
- **DeepSeek 偶发空回复的根因未定**（2026-08-12）：任务 `49be29b3`（助理，第 4 轮，带选区的长问题）的流跑了 4.9s 没有一个 `output_text.delta`，最可能是输出额度在第一个可见 token 之前被推理耗尽。再复现时把日志里的事件计数与 `reasoning_tokens` 补到这里。
- **`thinking: disabled` 在 Responses API 上无效**（2026-09-04）：不报错也不生效；当时的 deepseek-v4-flash 在 Responses 上每次都产生推理（80～270 个分片）并占用 `max_output_tokens`，所以走 Responses 的角色 `max_tokens` 要留足余量（当前 4096）。用 `tools/probe_llm_live.py P4` 复测。
- **CPA 网关上游间歇性成片失败**（2026-09-05）：`...: EOF`、`503 auth_unavailable` 等，几条路径会同时挂、几分钟后又好；小样本看不出哪个模型更稳。客户端按决策不重试（见下）。
- **CPA 网关不透传 `web_search_call` 事件**（2026-09-12）：检索本身正常，但没有「正在联网搜索…」占位，控制台结果行也没有 `(搜索)` 标签；要补需在网关侧改。
- **经 CPA 的 Gemini 回复是一次性整段 delta**（2026-09-05）：Toast 没有打字机效果，静默几秒后全文出现；智能时长从生成完成起算，不受影响。
- **待挂槽里的陈图**（2026-09-12）：时效检查只管剪贴板有多新，管不到图在待挂槽里躺了多久——被打断退回待挂的旧图会在下一次有效录音时照常发出，描边也看不出是哪张。若再出现，可考虑待挂超过 `vision_clipboard_max_age` 时给描边换色。
- **角色 Toast 字号偶尔显得偏大**（2026-09-07）：助理配置 18，重启后偶尔像 20 或更大，改值再改回后恢复，原因未定。复现时记录加载的字号、`font.actual()`/`metrics` 与 Tk scaling，和正常运行对比。
- **选区只读获取的盲区**（2026-09-15）：VS Code 普通编辑区要开 `editor.accessibilitySupport` 才读得到（未开时 UIA 返回空）；VS Code 集成终端（xterm.js 内部选区）与部分 TUI 的高亮读不到，只能用复制模式。按便携性约束，不做装扩展、改外部设置之类的方案。
- **OpenMate 的双屏全屏判定**（2026-09-07，外部项目）：OpenMate 的 `shouldDeferReminderForFullscreen()` 末尾仍把全局 `notificationState`（D3D/演示模式，不带显示器归属）当独立触发条件，前台已切到副屏的非全屏文档时仍可能延后提醒。应只改这个提醒判定函数：按前台窗口所在显示器判定，去掉全局状态这条触发。
## 仍然有效的决策

- **后端切换分两层**（2026-09-05）：角色文件选后端，`LLM/backends.py` 选模型、地址与超时。角色文件是配置面，一眼能看出走哪个后端；后端细节只写一处，改端口或令牌时不会漏掉某个角色、让它静默连不上。
- **后端不做重试、自动回退或多候选**（2026-09-05）：`RoleConfig` 在加载期定死，运行时切后端要改 `llm_handler`/`llm_processor` 这条「漏转发不报错」的路径；网关只在局域网可达，人不在网里时是超时而不是拒绝，自动回退会让每句话先白等几秒。失败由诊断日志如实报出。
- **后端能力缺口不在客户端开特例**（2026-09-05）：两套后端的角色配置保持一致（CPA 下同样开 `enable_web_search`），网关缺什么在网关侧补。
- **角色分段过多靠改提示词解决**（2026-09-13）：雾切响子、新岛真的简单回复以一条完整消息为主（50 字只作简洁参考，不再是拆条阈值），保留短句、语气和新岛真受惊/害羞时的短句连发；温度、后端、分隔符、发送器与已有历史都没改。没改成双换行分隔：DeepSeek 本来就常在短句之间输出双换行。
