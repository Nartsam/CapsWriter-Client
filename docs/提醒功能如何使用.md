# 提醒功能如何使用

对具名角色说一句「几点提醒我做什么」，到时由该角色提醒你。默认启用（`reminder_enabled`），修改 `config_client.py` 后需重启客户端。

## 使用方式

按住听写键并明确叫出角色，例如：

- 「助理，十分钟后记得让我站起来活动一下。」
- 「雾切响子，明天下午两点半提醒我喝水。」
- 「助理，查看待执行的提醒。」
- 「助理，取消明天下午两点半喝水的提醒。」

连续对话已进入具名角色时可以省略称呼。普通听写、default 角色、文件转录不处理提醒。
一次请求只创建或取消一条；明确不支持周期提醒、修改/改期和批量操作。取消描述必须唯一；正在交付的提醒已离开可取消列表。

判定为提醒的那句话只走提醒流程：不读选区、不带对话历史、不调用搜索，也不写角色对话记录、不做 UDP 广播；原始听写照常写进日记，连续对话照常进入或刷新；本句挂着的截图会被消耗，终端提示「提醒任务不使用图片」。模型判断不是提醒时，这句话再按普通角色请求处理。

## 时间与内容

- 时间基准是这句录音结束时间（`time_start + duration`），与网络和模型延迟无关；保存前再次检查至少还剩 15 秒。
- 没说日期的时刻取未来最近一次，并限制距录音结束不超过 6 小时。单说「两点半」按 02:30 解释，下午需明确说出；当前 15:00 时会因下一次 02:30 超过 6 小时拒绝创建。
- 明确日期已过去就拒绝。最远允许录音结束当日的后天 23:59:59；跨日不会因模型响应慢而扩大窗口。
- 「待会儿」「两三个小时」「下班后」等不明确时间不创建。例如：`提醒未设置：“待会儿”未明确指定时间，请给出具体时刻。`
- 事项必须独立完整，不引用上一轮对话或选中文字。简洁事项 `subject` 上限 120 字，角色提醒文案上限 300 字，均为单行纯文本。
- 创建时一次 LLM 请求同时生成时间语义、事项与角色风格提醒文案；到期不再调用 LLM。角色语气取自创建时提示词。文案要求自然表达提醒含义，避免照抄事项或孤立动作指令，具体措辞与标点由模型按角色和本次语境决定；不机械拼接前缀、不新增润色调用。提示词调整仅影响新建提醒，已有文案保持创建时快照。
- 同角色、同一秒、规范化后相同事项判为重复，返回已有提醒的确认，不新增。

创建通知固定为：`提醒已设置：今天 15:10:00「助理」会提醒你站起来活动一下`。
今天/明天/后天按实际通知时间计算；「会提醒你」与事项直接连接。

## 展示与 OpenMate

创建、拒绝、查看、取消及重启过期汇总都是客户端内部状态：主屏底部居中、不可拖动、固定超时；鼠标悬停或滚动不会延长显示。长列表可滚动。这些状态始终不发送 OpenMate。

内部状态采用独立样式：默认 18 号字体（Tk 磅值）、浅暖黄底 `#FFF4D6`、深色字 `#332B1A`、不透明圆角窗口。宽度按实际文本扩展，最小 480 像素，最大为 1600 像素与主屏宽度 80% 中较小者；小屏最小宽度随上限收缩。超过上限的长文案仍自动换行。角色窗口与其他普通通知样式不受影响。

运行中正常到期采用普通角色 Toast 的样式、智能时长、拖动和新窗口替换行为。到期前处于全屏、锁屏或屏保时保留待执行状态；离开后一次合并本地积压提醒，同角色保留角色样式，混合角色使用默认样式。

实际投递比计划时间晚不超过 10 秒（含边界）视为准时，不显示时间前缀，不论是否曾因全屏/锁屏暂停。超过 10 秒才显示经过时间。本地延迟或合并展示保留角色名，合并时逐条判断是否加时间前缀，例如：

```text
1小时10分钟前，「雾切响子」：坐得够久了，起来活动一下。
```

经过时间按实际投递时刻减到期时刻计算，截断小数，最多显示两个最大的非零单位；不足一秒为「刚刚」。

到期时根据当前全局和角色 OpenMate 开关选择路由。启用且健康时使用 `POST /v1/message-batches`，单条也走批次 API；失败回退本地。每条发送稳定提醒 ID、文本，以及创建时显式配置的 `openmate_character`。未显式配置时省略 character，不继承全局角色，让 OpenMate 当前角色展示。配置在创建后变更不会修改已存的目标角色。省略 `tts`，遵循 OpenMate 角色自身的自动朗读配置。

OpenMate 延迟文案无角色名：

```text
<notts:1小时10分钟前，>坐得够久了，起来活动一下。
```

`notts` 内文本显示但不合成语音。只有明确目标角色且能取到状态列表时，创建分析才选择情绪；到期重新核验状态仍存在，失败则省略。目标角色是否实际切换由 OpenMate 负责。

## 队列与恢复

解析失败通知会区分空正文、JSON 语法/重复字段、响应未完成、字段缺失、时间字段、情绪状态和调用异常。诊断以 INFO 写入 `logs/client_latest.log`，不额外输出终端：JSON 错误只保留位置附近最多 240 字符，字段失败记录字段名、时间和状态摘要，不保存完整请求或角色提示词。文件日志级别需保持 INFO 或 DEBUG。

待执行事件保存在 `logs/reminders.json`（UTF-8 无 BOM）。创建/取消采用同目录临时文件、flush/fsync、原子替换，持久化成功后才告知成功。目标文件不存在或内容无效时，启动过程会自动创建空的合法快照；只有该空快照也无法写入时才禁用本次提醒服务。

重启后：未来提醒继续；过去 6 小时内的到期事件在软件资源就绪后立即合并为内部状态通知，直接显示事项，不使用角色语气，也不等待全屏退出；更早事件静默过期并记日志。提醒恢复不依赖 ASR 连接成功。

运行中到期的角色提醒由客户端和 OpenMate 各自检查全屏。Client 仅关注当前前台窗口所在显示器：主屏游戏仍在后台、副屏文档成为前台时可以提示，Toast 仍显示在主屏。使用 Win32 API，无新增依赖；只有存在已到期事件时才每秒复查，无待执行事件时不做全屏探测。

交付成功定义为本地 Toast 窗口已创建，或 OpenMate 已返回接受回执，随后移出 Client 持久化队列。它不代表用户已阅读或 TTS 已播放完。

已接受的限制：

- Client 显示/投递成功与完成状态落盘之间崩溃，重启可能重复提醒；退出时 HTTP 工作线程仍可能完成请求，亦有此窗口。OpenMate 请求超时但实际接受时，本地回退也可能重复。
- OpenMate 批次队列暂不持久化。已返回接受回执后 OpenMate 意外退出，尚未展示的内容可能丢失；当前未考虑/处理恢复或重新投递。
- 客户端退出期间无法按时提醒；系统时钟变更按当前系统时间调度，不做额外时钟校正。
- 意图与时间由 LLM 判断：解析超时、截断或格式非法会显示失败；只有严格的 `none` 才串行进入普通角色请求。本地预筛要求提醒相关词或时间线索（数字加时间单位、时刻/日期格式或「明天、待会」等表达），任一命中即可；「5分钟后提醒我一下」「五分钟后起来活动」「半小时后喝水」仍会进入分析，「介绍一下」「输出200字」直接进入普通聊天。提到时间、讨论提醒的普通问题仍可能额外调用一次 LLM，最终由模型判断意图。

## 配置

配置均位于 `config_client.py` 的 `ClientConfig`。表中是缺省值（配置项缺失或取值非法时使用），以 `config_client.py` 里实际写的值为准：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `reminder_enabled` | `True` | 提醒入口与调度总开关 |
| `reminder_implicit_date_max_hours` | `6` | 没说日期的时刻最多距今几小时 |
| `reminder_min_lead_seconds` | `15` | 解析完成后最少剩余秒数 |
| `reminder_overdue_max_hours` | `6` | 重启补报的过期时长窗口 |
| `reminder_max_pending` | `50` | 待执行事件上限 |
| `reminder_request_timeout` | `60` | 独立 LLM 分析等待上限（秒） |
| `reminder_status_duration` | `6000` | 内部通知固定时长（毫秒，1000～60000） |
| `reminder_status_font_size` | `18` | 内部通知独立字号（Tk 磅值，8～48），不跟随角色配置 |

独立分析沿用角色 provider、URL、密钥、模型、温度和 API 路径；custom 固定使用非流式 Responses。DeepSeek / custom 的分析采用后端默认思考设置，不跟随角色的 `thinking_level`；不合并 `extra_options`，不注入历史、选区、图片、工具和搜索。输出额度至少 2048，避免结构化任务被过小的普通回复限额截断。普通角色调用保持原配置。
